# 不具合報告と対応

状態の凡例: **解決済**(実機で確認済み) / **対応済・未確認**(修正したが実機で未確認) / **未解決** / **不具合ではない**

## D1. local.properties に書いた App key が消える — 解決済

- 現象: Claude が `local.properties` に `dropbox.appKey=...` を書き込んだが、アプリで「App key が未設定です」と出た。ファイルを見ると空に戻っていた
- 原因: Android Studio でそのファイルを開いていたため、エディタ上の古い内容で上書きされた
- 対応: Android Studio のエディタで直接書き換えて保存
- 教訓: **Claude が PC のファイルを書き換えるときは、そのファイルを Android Studio で開いていないこと**(setup.md 参照)

## D2. App key を書いても「App key が未設定です」 — 解決済

- 原因: App key はビルド時に BuildConfig へ埋め込むため、書いた後に再ビルドが必要
- 対応: Sync Project with Gradle Files → Rebuild Project → Run

## D3. サムネイルがいつまでも表示されない — 解決済

- 現象: グリッドが灰色のまま。Logcat に `com.dropbox.core.BadRequestException: Error in call to API function "files/get_thumbnail_batch": entries: unexpected key 'quality'`
- 原因: Dropbox Java SDK 7.1.0 が `ThumbnailArg` に `quality` キーを付けて送るが、現在の API はこのキーを受け付けない。撮影日時の取得も同じ API を使っていたが、失敗時に `get_metadata` へ切り替える処理があったため、並び順だけは正しく見えていた
- 対応: `get_thumbnail_batch` と `get_thumbnail_v2` を SDK を通さず HTTP で直接呼ぶ `ThumbnailApi.java` を追加(グリッド・ビューア・撮影日時取得の3か所)。アクセストークンは `DropboxClientProvider.getFreshAccessToken()` で取得・更新
- あわせて: サムネイル取得スレッドが例外で止まらないよう `Throwable` を捕捉
- 注意: SDK を新しい版に上げる場合、この問題が直っていれば SDK に戻すこともできる。SDK 8.x は Java 21 が必要

## D4. 引っぱって更新のくるくるが止まらない — 対応済・未確認

- 原因: 終了条件が「一覧取得+全写真の撮影日時取得」だった。写真が多いと後者に時間がかかる(サムネイル取得は無関係)
- 対応: 一覧取得完了+最新100件の撮影日時取得で終了。残りは裏で継続し、サブタイトルに進捗を表示(R12)

## D5. 年・月・日の切り替えが効かない/メニューは「月」なのに日ごとに並ぶ — 対応済・未確認

- 現象: メニューで「月」がチェックされているのに、日単位の見出しで表示されていた
- 原因: 当時はピンチで年・月・日を切り替える仕様だった。3本指スクリーンショットなどがピンチと判定されて「日」に変わり、そのときメニューのチェックを更新していなかった
- 対応: ピンチは2本指のみ反応、メニューのチェックも更新。その後、ピンチは列数変更だけに仕様変更(R15)したため、ピンチで年・月・日が変わることはなくなった

## D6. 年・月・日を切り替えてから並ぶまで時間がかかる — 対応済・未確認

- 原因: ListAdapter の差分計算(DiffUtil)。切り替えでは見出しが総入れ替えになり、数千件だと数秒かかる
- 対応: 切り替え時だけ差分計算をせず `submitList(null)` → `submitList(新リスト)`。直前に見ていた写真の見出し位置へスクロールし直す

## D7. フォルダやサブフォルダ設定を切り替えると古い日付から表示・取得が始まる — 対応済・未確認

- 原因: 全件取得では Dropbox が日付と無関係な順(フォルダ順)で返すのに、ページ(最大2000件)ごとに画面へ反映していた。古いフォルダが先に来ると古い写真が先に表示され、サムネイルも古い順に取りに行っていた
- 対応: 全件取得のときは全ページそろってから一度に反映。差分取得はページごとのまま

## D8. 2026年11月より新しい写真が出ない — 不具合ではない

- アプリの表示(11月 1件、10月 11件)は公式 Web の「写真」と一致していた。Dropbox に上がっている写真はすべて出ている

## D9. 月ごとの件数が公式 Web と合わない — 未解決

- 現象: 2026年9月がアプリでは 22 件、公式 Web では 10 件。公式 Web はアカウント全体が対象なので、本来は Web の方が多いはず
- 仮説: 撮影日時(media_info)が取れなかった写真が、ファイルの更新日時(client_modified)で 9 月に並んでいる。公式は別の基準で並べている可能性
- 次の調査: 9月の中で Web に出ていない写真をビューアで開き、日付の後ろに「(更新日時)」と出るか確認する

## 作業環境起因の問題(参考)

- Claude のクラウド作業環境からは Google Maven / Maven Central / Gradle 配布サイトに接続できず、ビルドできない。ビルドと実行は PC の Android Studio で行う
- Claude が Dropbox SDK の生成コードを Stone で生成して API 名を確かめようとした操作は許可されなかった。SDK と API 仕様のソースを読んで確認した
