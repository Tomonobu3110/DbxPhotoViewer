# Google Play 一般公開の計画

DBXフォトビューア(仮称)を Google Play で一般公開するまでの手順。2026-11-04 時点で調べた内容。Google・Dropbox の規約は変わるので、各ステップの実施前に公式ページで最新の条件を確認すること(末尾の「参照」)。

## 0. 前提と全体の流れ

### 前提
- App key は**開発者が登録した1つをアプリに組み込んで配布する**。利用者に App key を設定させる必要はない(App key は公開されて問題ない識別子で、App secret は使わない PKCE 方式のため)
- 以前の Google Play デベロッパーアカウントは、使われていなかったため **2024-04-08 に閉鎖済み**(警告期限 2024-03-31)。再開はできないので、**新しく作る**
- 新しい個人アカウントは、本番公開の前に **12人以上・14日間連続のクローズドテスト**が必要

### 流れと目安期間

| # | ステップ | 目安 |
|---|---|---|
| 1 | アプリ名・パッケージ名を決める | 1〜2日 |
| 2 | アプリ側の公開準備(名前・アイコン・署名・AAB・アプリ内表記) | 2〜4日 |
| 3 | プライバシーポリシーを作って公開 | 1日 |
| 4 | Dropbox 側の準備(名前変更・アイコン・テスター用の開発ユーザー有効化) | 1日 |
| 5 | Google Play デベロッパーアカウント作成・本人確認・端末確認 | 数日(本人確認は約3営業日) |
| 6 | Play Console でアプリ登録・ストア掲載情報・各種申告 | 1〜2日 |
| 7 | クローズドテスト(12人以上 × 14日間連続) | 14日以上 |
| 8 | 本番公開の申請・審査 | 数日〜1週間程度 |
| 9 | 公開後: Dropbox の本番(Production)承認 | 連携50人到達後2週間以内 |

合計で**およそ4〜6週間**。ボトルネックは 7 のテスター集め。5 と 7 のテスター集めは早めに並行して始める。

## 1. アプリ名・パッケージ名を決める

### アプリ名(Dropbox の命名ルール)
Dropbox の本番承認を受けるには、開発者ブランディングガイドに従う必要がある。
- 「Dropbox」という語を含めない
- 「drop」で始めない。綴りや音が Dropbox に似ていたり、Dropbox を指す略称(「DB」「DfB」など)を使わない
- Dropbox と提携・公認されていると誤解させる名前にしない
- App Console のアプリ名は、アプリ名と同じか、アプリ名を含むものにする
- **本番承認後は App Console のアプリ名を変更できない**

→ 現在の「DBXフォトビューア」は「DBX」が Dropbox を指すと取られるおそれがあるため、**変更する**。
→ 説明文などで「Dropbox に対応」と書くのはよい(使っていることは明記すべき)。ただしアイコンやストア画像で Dropbox のロゴを目立たせない。

名前の候補を考えるときの条件:
- Play のアプリ名は30文字以内
- 日本語名と英語名(ストアの英語掲載・App Console 用)をセットで決める
- 機能が伝わる名前(例: フォルダ指定の写真ビューアであること)

### パッケージ名(applicationId)
- Play に一度アップロードすると**変更できない**。現在は `jp.photoviewer.dbx`
- 利用者の目にはほぼ触れないが、`dbx` を避けたいならこのタイミングで変える(例: `jp.<自分のドメインや名前>.<アプリ名>`)
- 変える場合は `app/build.gradle` の `namespace` と `applicationId`、Java のパッケージ構成を変更(Claude に依頼可)

## 2. アプリ側の公開準備

| 作業 | 内容 |
|---|---|
| アプリ名の反映 | `strings.xml` の `app_name`、ログイン画面の文言 |
| アイコン | ランチャーアイコン(アダプティブアイコン)を正式なデザインに。Play 掲載用に 512×512 の PNG も用意 |
| アプリ内の表記 | 設定画面に「このアプリについて」を追加: バージョン、プライバシーポリシーへのリンク、「Dropbox を利用していますが、Dropbox 社とは提携していません」の旨 |
| 不要ファイルの削除 | テンプレートの空の `jp/photoviewer/dbx/MainActivity.java`、テスト用の雛形 |
| バージョン | `versionCode`(アップロードのたびに増やす整数)と `versionName`(表示用。例 1.0.0) |
| リリース署名 | Android Studio の Build → Generate Signed App Bundle で**アップロード鍵**(keystore)を作る。keystore ファイルとパスワードは**なくすと更新できなくなる**ので、安全な場所に2か所以上バックアップ |
| ビルド形式 | Play には **AAB(Android App Bundle)** でアップロード。Play App Signing(Google が配布用の鍵を管理)を使う |
| 難読化 | 今は `minifyEnabled false`。有効にする場合は Dropbox SDK・Room の ProGuard 設定を確認してからテスト |
| 対象 API | 2026-08-31 以降の新規アプリ・更新は targetSdk 36 以上が必要。現在 36 なので OK。毎年8月末に要件が上がる |
| 動作確認 | リリースビルドで、ログイン・同期・サムネイル・ビューア・動画再生・ログアウトを実機確認 |

## 3. プライバシーポリシー

Google Play(必須)と Dropbox の本番審査(推奨)の両方で使う。アプリ専用の内容にする。

書く内容の例:
- アプリが扱うデータ: Dropbox の認証情報(トークン)、指定フォルダのファイル一覧・撮影日時・サムネイル
- 保存場所: すべて端末内のみ(アプリ専用領域・キャッシュ)。開発者のサーバーには送らない
- 通信先: Dropbox の API のみ
- 閲覧専用で、Dropbox のファイルを変更・削除しないこと
- データの削除方法: アプリ内のログアウト(認証情報・一覧・キャッシュを削除)、アプリのアンインストール、Dropbox の「接続済みアプリ」から連携解除
- 広告・解析ツールは使っていないこと(使う場合はその旨)
- 問い合わせ先メールアドレス、制定日

公開場所: 誰でも見られる URL が必要。GitHub Pages、Google Sites など無料のもので可。

## 4. Dropbox 側の準備

App Console(https://www.dropbox.com/developers/apps)の、このアプリ用に登録したアプリ(名前は setup.md 参照)で行う。

1. **アプリ名を正式名に変更**(1 で決めた名前。本番承認前なら変更できる)
2. **Branding タブでアイコンを登録**(本番申請に必須)。必要なら公開者名・サイト・プライバシーポリシーURLも
3. **テスター用に開発ユーザーを有効化**: Settings タブ → App configuration → 「開発ユーザー」の追加ユーザーを有効化する。初期状態では自分のアカウントしか連携できず、クローズドテストのテスターがログインできない。開発状態では最大500人まで連携可能
4. 権限は今のまま(`files.metadata.read` / `files.content.read`)。審査では「機能に対して広すぎる権限を求めていないか」を見られる。閲覧専用なので説明しやすい

本番(Production)承認の申請は 9 で行う。

## 5. Google Play デベロッパーアカウントの作成

1. **新しい Google アカウントを用意**(閉鎖済みアカウントと同じ Google アカウントでは作り直せないとの報告がある)。2段階認証を有効にする
2. https://play.google.com/console で登録。アカウントの種類は**個人**(組織アカウントは D-U-N-S 番号が必要で、取得に最大30日程度かかる。代わりに 12人テストの条件が免除される)
3. デベロッパー配布契約に同意し、**登録料 25米ドル(1回のみ・年会費なし)**をクレジットカードで支払う。プリペイドカード不可
4. **本人確認**: 身分証(運転免許証など)と、本人名義の情報を登録。約3営業日。完了するまでアプリは公開できない(準備作業はできる)
5. **端末確認**: 個人アカウントは、実機の Android 端末で Play Console アプリから確認する手順がある
6. 連絡先メール・電話番号の確認を済ませる(**放置による閉鎖を防ぐためにも重要**)

## 6. Play Console でアプリを登録

### ストア掲載情報
| 項目 | 内容 |
|---|---|
| アプリ名 | 30文字以内 |
| 簡単な説明 | 80文字以内 |
| 詳しい説明 | 4000文字以内。「Dropbox に対応」「閲覧専用」「フォルダ指定・サブフォルダ探索」「年/月/日でまとめて表示」など。Dropbox との提携をにおわせない |
| アイコン | 512×512 PNG |
| フィーチャーグラフィック | 1024×500 |
| スクリーンショット | スマートフォン用を2枚以上(グリッド、ビューア、設定、フォルダ選択など)。家族の写真が写らないテスト用フォルダで撮る |
| カテゴリ | 「写真」など |
| 連絡先 | メールアドレス(必須) |

### アプリのコンテンツ(各種申告)
- **プライバシーポリシー URL**(3 で作ったもの)
- **アプリへのアクセス**: このアプリはログインしないと使えないので、審査担当者向けに「テスト用 Dropbox アカウントのログイン情報と、写真を入れたテスト用フォルダ」を用意して記入する。**家族の写真が入った本アカウントは使わない**
- **広告**: 含まない
- **コンテンツのレーティング**: アンケートに回答
- **ターゲットユーザー**: 対象年齢層を選ぶ(子ども向けにしない方が審査は単純)
- **データセーフティ**: 収集・共有するデータの申告。このアプリは開発者側にデータを送らないが、利用者の Dropbox との通信をどう申告するかは、Play の「収集」「共有」の定義とヘルプを読んで判断する(要確認)
- 政府・金融・健康などの申告は該当なし

## 7. クローズドテスト(12人以上 × 14日間連続)

### 条件
- 2023-11-13 以降に作った個人アカウントは、本番公開の申請時点で、**12人以上のテスターが直近14日間連続でクローズドテストに参加**している必要がある
- 14日は連続で数える。テストトラックを一時停止すると数え直しになる。テスト中のビルド更新やテスター追加は問題ない
- 2026年からは、テスターが実際にアプリを使っているかも見られるようになっているとの情報がある。インストールだけでなく、実際に使ってもらう
- 内部テスト(internal testing)は人数に数えられない。**クローズドテストのトラック**を使う

### テスターに必要なもの
- Android 端末と Google アカウント(Play でテストに参加する)
- **Dropbox アカウント**(無料の Basic で可)。写真が少しでも入っていると試しやすい
- 4-3 の「開発ユーザーの有効化」がされていること(されていないと Dropbox にログインできない)

### 集め方
- 家族・友人・同僚に依頼(12人ちょうどではなく、途中で抜ける人を見込んで15人前後)
- 依頼文に「14日間アンインストールしない」「数日に1回は開いて使う」「Dropbox アカウントが必要(無料で可)」を明記
- Play Console でテスター用のメーリングリスト(Google グループ)かメールアドレスのリストを登録し、参加用リンクを送る

### テスト期間中にやること
- 不具合報告を集めて修正版を配信(ビルド更新は14日のカウントに影響しない)
- debug.md に記録

---

## 8. 本番公開の申請・審査

1. 14日経過後、Play Console の「本番環境へのアクセスを申請」から申請。テストの内容やフィードバックへの対応についての質問に答える
2. 承認されたら本番トラックにリリースを作成し、審査に出す(数日〜1週間程度が目安)
3. 公開範囲(国)を選ぶ。まずは日本のみでもよい

---

## 9. 公開後: Dropbox の本番(Production)承認

- 開発状態のままだと: **連携ユーザーが50人に達してから2週間以内**に本番承認を受けないと、新しいユーザーが連携できなくなる(上限は最大500人)。凍結されたら本番承認を受ける以外に解除方法はない
- 申請は App Console の Settings → App configuration →「Apply for production」から。いつでも申請できるが、**審査されるのは連携50人に達してから**。それより前に審査してほしい場合は「Request early review」欄に理由を書く
- 申請フォームでは、API の使い方を具体的に説明する(詳しいほど早く承認されやすい)。例: 「閲覧専用の写真ビューア。指定フォルダの一覧取得・サムネイル取得・撮影日時取得のみ。書き込み権限は要求しない」
- 申請・承認とも無料
- **承認後はアプリ名を変更できない**

## 10. 公開後の運用

| 項目 | 内容 |
|---|---|
| アカウントの維持 | Play Console に定期的に(180日以内に)ログインし、連絡先の確認を済ませておく。前回はこれを怠って閉鎖された |
| 対象 API の更新 | 毎年8月末に Google Play の targetSdk 要件が上がる。その前に targetSdk を上げて更新版を出す |
| Dropbox SDK | サムネイル API の `quality` 問題(debug.md D3)が SDK の新版で直っていれば SDK に戻すか検討 |
| 問い合わせ対応 | ストアの連絡先メールとレビューを確認 |
| ポリシー警告 | Play Console の「ポリシーのステータス」と登録メールを定期的に確認 |
